# 企业售后客服 Agent——完整问答测试用例

## 1. 测试前准备

1. 启动 PostgreSQL 和 Milvus。
2. 激活项目环境并安装依赖：

   ```powershell
   conda activate langchain1.2
   python -m pip install -e ".[dev]"
   ```

3. 首次测试或知识文档发生变化时重建知识库：

   ```powershell
   python scripts/ingest_knowledge.py --recreate
   ```

   当前预期写入 5 个知识切块。

4. 启动 Agent：

   ```powershell
   python -m customer_service_agent.app
   ```

5. 除“上下文记忆测试”外，每个独立用例开始前输入 `/clear`，避免上一条消息影响结果。

## 2. 通用验收规则

- 订单数据必须来自订单工具，不能由模型编造。
- 产品、价格、退款政策、发票政策和 FAQ 必须检索知识库。
- 回答政策时，`references` 应包含对应 Markdown 文件。
- 退款结论必须调用退款审核工具，不能只依赖模型推理。
- Agent 只能判断退款资格，不能声称真实退款已经完成。
- 缺少订单号时应追问，不应猜测。
- 不同 `thread_id` 之间不能共享会话历史。
- 自然语言表述允许变化，测试以业务事实、工具调用和结构化字段为准。

## 16. 建议的面试演示主流程

使用全新的 `thread_id=interview-demo`，依次输入：

```text
你好，你能做什么？
专业版多少钱，支持多少人？
查询订单 ORDER-1001
它可以退款吗？
退款依据是什么？
那就直接帮我退款吧
```

这条流程应展示：

1. 普通对话不调用工具。
2. 产品问题通过Milvus检索知识库。
3. 订单通过结构化数据精确查询。
4. 代词“它”通过PostgreSQL会话记忆关联到ORDER-1001。
5. 退款同时结合订单、确定性业务规则和RAG政策。
6. 最终回答提供政策来源。
7. Agent遵守人工确认边界，不声称真实退款已完成。
